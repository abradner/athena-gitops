# GitOps Setup Audit — July 2026

Scope: full review of `athena-gitops` (manifests, bootstrap scripts, secrets
handling, repo hygiene). Findings are ordered by priority. Items marked
**✅ fixed in this branch** were implemented alongside this report; the rest
are recommendations.

## What's already good

- **Secrets hygiene is solid.** Talos configs are committed as templates with
  `{{ dotted.key }}` placeholders; hydrated files are gitignored
  (`bootstrap/talos/.gitignore`), and a scan found no committed certs, keys,
  or tokens. All runtime secrets flow through ESO + 1Password.
- **Sync-wave ordering is used correctly** — the `ClusterSecretStore` and
  `ExternalSecret`s are wave 1 with `SkipDryRunOnMissingResource`, so the ESO
  CRDs land first on a cold rebuild.
- **Third-party Helm charts are version-pinned** (metrics-server 3.13.0,
  headlamp 0.24.1, external-secrets 2.2.0).
- **The DR playbook exists and is ordered** (`bootstrap/README.md`) — most
  homelabs don't have one.

## High priority

### 1. The DR playbook depends on a file that isn't in the repo — ✅ fixed
`bootstrap/talos/apply-control.sh`, `apply-worker.sh`, and
`bootstrap/mise.toml` all source `bootstrap/athena.zsh`, and the README's
directory listing implies it's committed — but it isn't (and it wasn't
gitignored either, so its absence was invisible). A fresh clone during a
late-night disaster recovery would fail at step 3.
**Fix:** added `bootstrap/athena.template.zsh` documenting the required
variables, gitignored the real `athena.zsh`, and noted in the README that the
real copy should be backed up (e.g. in the 1Password vault next to the Talos
secrets note). Verify the template's variable list matches your real file.

### 2. No CI — validation was local-only — ✅ fixed
The pre-commit hook lives in `.git/hooks/` (not committed), so nothing
enforced validation server-side, and syntax-only checking wouldn't catch a
schema typo that Argo CD then auto-applies to the cluster.
**Fix:** added `.github/workflows/validate.yaml` running
`scripts/validate_yaml.sh` plus kubeconform (strict, with the datree CRD
catalog for Argo CD / ESO / Gateway API schemas) on every push and PR.
Consider adding a branch-protection rule on `main` requiring this check —
with `prune: true` + `selfHeal: true`, merging to `main` *is* deploying.

### 3. Token-loading script invited editing a secret into a tracked file — ✅ fixed
`bootstrap/kubernetes/load1p-account-token.sh` (and the README) instructed
editing the script to paste in the 1Password Service Account token — one
absent-minded `git add` away from a leaked cluster-wide secrets credential.
**Fix:** the script now reads `OP_SERVICE_ACCOUNT_TOKEN` from the environment
(sourced via `op read`), refuses to run without it, and is idempotent for DR
re-runs.

### 4. ~360 lines of copy-pasted Application manifests — ✅ fixed
`pmn-dev4.yaml` and `pmn-dev5.yaml` were 20 near-identical `Application`
resources differing only in service name and env. Every new env is a
copy-paste of ~180 lines; drift between envs is invisible.
**Fix:** replaced with `cluster/apps/pmn-appset.yaml` — an `ApplicationSet`
with a matrix generator (10 services × 2 envs). Generated names match the old
ones exactly (`pmn-core-dev4`, …) so the controller adopts the existing apps
in place without recreating workloads. Adding an env is now a one-line change.
**⚠️ Before merging:** if `tools-workflow`'s `GenerateArgocd` still
regenerates `pmn-dev*.yaml` files, update it to edit the ApplicationSet lists
instead — regenerated per-env files would fight the ApplicationSet for
ownership of the same-named Applications.

## Medium priority

### 5. Bootstrap installs are partially unpinned and non-idempotent — ✅ partially fixed
`provision.sh` installed Argo CD from the moving `stable` manifest URL and
Cilium config lived in a wall of `--set` flags; `kubectl create namespace`
made re-runs fail.
**Fix:** versions are now variables at the top of the script (Argo CD accepts
`ARGOCD_VERSION` from the environment, still defaulting to `stable` —
**recommend pinning it to the tag you're actually running**), Cilium values
moved to `bootstrap/kubernetes/cilium-values.yaml`, `helm upgrade --install`
and dry-run-apply namespace creation make the script re-runnable, and
`set -euo pipefail` stops it from blowing past a failed step during DR.

### 6. Everything runs in the `default` Argo CD project — ✅ fixed (round 2)
Every Application (and the root app) used `project: default`, which allows
any source repo and any destination.
**Fix:** `cluster/projects.yaml` defines the `core` project (this repo +
the pinned chart repos → infra namespaces) and the `pmn` project
(`pmn-workloads` → `pmn-*` namespaces only), and every Application/the
ApplicationSet template now references them. The projects are synced by the
root app itself (they must exist before the children that use them). The
root stays in `default` — it's the bootstrap entry point. `pmn`'s
`clusterResourceWhitelist` is left permissive with a TODO to tighten once
the overlays are confirmed namespace-scoped.

### 7. One recursive root app owns the world — ✅ fixed (round 2)
`root-app.yaml` recursively synced all of `cluster/` in a single app with
`prune: true`: no per-area sync status, one giant diff view, and a single
bad directory rename could prune core infrastructure.
**Fix:** the root moved to `cluster/root.yaml` (inside its own sync path,
so it now manages its own spec — no more silent drift between the file and
the live app) and syncs only the top level of `cluster/` non-recursively
with `prune: false`. `cluster-core.yaml` and `cluster-apps.yaml` own their
directories with automated prune/self-heal/retry.
**Migration is adoption-only:** the first sync under the old live spec sees
only *added* files (nothing removed), so nothing is pruned; the root then
self-updates to non-recursive/prune-off, orphaning the subtree, and the two
children adopt every resource in place (same names/namespaces — relabel,
not recreate).
Child Applications still carry no `resources-finalizer` — deleting one from
git orphans rather than cascade-deletes; add finalizers deliberately if you
want cascade. (The pmn ApplicationSet keeps `preserveResourcesOnDeletion:
true` and no finalizer for the same reason.)

### 8. hello-world test resources live alongside production config
`cluster/apps/hello-world/` contains a raw Deployment/Service/HTTPRoute plus
`test-external-secret.yaml`, which writes `my-locally-injected-secret` into
the `default` namespace on every sync. Useful as an ESO/gateway canary, but
it's synced with the same prune/self-heal authority as everything else.
**✅ Fixed (round 2):** the canary now has its own `Application`
(`cluster/apps/hello-world-app.yaml`); `cluster-apps` excludes the
`hello-world/` subtree so it can be paused or pruned independently. Kept in
the `default` namespace on purpose — the live resources are adopted
in place rather than recreated. The Deployment also gained
requests/limits and readiness/liveness probes.

### 9. Ingress for cluster services is managed imperatively
`argocd-gateway.yaml` and `hubble-gateway.yaml` are only applied by
`provision.sh` — Argo CD doesn't manage them, so any later edit is invisible
drift. The Gateway itself and the Cilium IP pool are in the same boat
(defensible, since they're CNI-adjacent bootstrap, but the HTTPRoutes aren't).
**✅ Fixed (round 2):** the two HTTPRoutes now live in
`cluster/core/networking/` and are adopted by `cluster-core`; bootstrap
still applies them once during provisioning (the Argo CD UI is needed
before the root app exists), but post-bootstrap edits belong in git. The
Gateway + Cilium IP pool intentionally stay bootstrap-only (CNI-adjacent).

## Low priority

- **`targetRevision: HEAD`** — ✅ fixed (round 2) for this repo's own
  sources (`main`). The pmn ApplicationSet still uses `HEAD` for
  `pmn-workloads` deliberately: its default-branch name wasn't verifiable
  from here — pin it once confirmed.
- **cert-manager** — ✅ scaffolded (round 2): the chart is installed via
  `cluster/core/cert-manager/cert-manager-app.yaml` (pinned, CRDs enabled),
  but **no Issuers yet** — choosing ACME + DNS-01 for `*.athena.asn.casa`
  vs. a private CA for LAN-only trust is an owner decision; issuers and a
  Gateway HTTPS listener are the follow-up (`hello.bradner.net` on plain
  HTTP is worth revisiting then).
- **`--kubelet-insecure-tls` on metrics-server**: Talos supports proper
  kubelet serving certs — set `machine.kubelet.extraConfig.serverTLSBootstrap: true`
  and run kubelet-csr-approver, then drop the flag. Left alone: it changes
  node machine config and needs a maintenance window.
- **hello-world Deployment** — ✅ fixed (round 2): requests/limits + probes.
- **Argo CD itself isn't GitOps-managed** (installed once from manifests,
  patched imperatively for `server.insecure`). Long-term: manage it with the
  argo-cd Helm chart via an Application so upgrades are declarative. Left
  alone: migrating a live install from raw manifests to the chart deserves
  its own carefully-staged change.
- **Automated dependency updates** — ✅ added (round 2): `renovate.json5`
  with the `argocd` manager pointed at `cluster/`. Requires enabling the
  Renovate GitHub App for the repo before it does anything.
- **Empty scaffolding** (`event-crm-staging/`, `event-crm-prod/` `.keep`
  files) — harmless, but delete if the plan changed.
- **`.ki/metadata.json` referenced a nonexistent `AI_ONBOARDING.md`** —
  ✅ fixed (now points at `AGENTS.md`). Also added a root `README.md`; the
  repo previously had onboarding docs for AI agents but not for humans.
- **Root app now has a `retry` policy** — ✅ added (transient failures during
  a cold rebuild previously left the sync failed until manual intervention).

## Suggested next steps (in order)

Round 1 (merged in PR #2) covered findings 1–5; round 2 covered 6–9 and
most low-priority items. Remaining, all owner decisions:

1. Enable branch protection on `main` requiring the `validate` workflow,
   and enable the Renovate GitHub App.
2. Choose the cert-manager issuance strategy (ACME/DNS-01 vs private CA),
   add Issuers + a Gateway HTTPS listener.
3. Pin the pmn ApplicationSet's `targetRevision` once `pmn-workloads`'
   default branch is confirmed, and tighten the `pmn` project's
   `clusterResourceWhitelist`.
4. Kubelet serving certs (Talos `serverTLSBootstrap` + kubelet-csr-approver)
   to drop `--kubelet-insecure-tls` — needs a node maintenance window.
5. Migrate the Argo CD install itself to chart-based GitOps management.
